Reusable manuscript toolchain

Run from the repository:
  bash scripts/build_manuscript_container.sh

Or process another host checkout (including a path containing spaces):
  bash scripts/build_manuscript_container.sh /absolute/path/to/checkout

The host folder must contain paper.tex, references.bib and build_paper.sh.
paper.pdf and the LaTeX logs are written to that same host folder, owned by
the invoking user. Manuscript sources are never copied into the image.

The image reference in image.txt is immutable. Docker downloads the image
only when it is absent locally. --rm removes the temporary execution
container, NOT the image, registry version or host files. Do not delete the
GHCR version referenced by image.txt. A fresh GitHub runner downloads this
prebuilt image; it does not rebuild it or install TeX.

The consumer has no apt step. It runs without network, with a read-only
container root filesystem, dropped capabilities and no registry token in
the TeX process. No persistent container service is necessary.

If the GHCR package is private, authenticate Docker with read:packages
access first. The repository workflow uses its scoped GITHUB_TOKEN; public
packages can be pulled anonymously. Visibility is an owner decision.

Toolchain update procedure:
  1. Review changes to Dockerfile or build-manuscript.
  2. Run the manuscript toolchain image workflow. It builds once and must
     pass the real-document, unresolved-reference and stale-PDF negatives
     before publishing. PRs never publish packages.
  3. Take the digest and package inventory from texlive-image-provenance.
  4. Explicitly update image.txt in a reviewed commit. Never use latest.
  5. Run the manuscript workflow, including the positive/negative checks.

Base Ubuntu is digest-pinned. Apt package resolution may change on a new
image build; every image records dpkg-query output at
/usr/local/share/abs-texlive/packages.tsv and carries source/revision labels.
Image pinning reproduces a chosen toolchain; it is not a promise that
rebuilding the Dockerfile later yields identical bytes.
