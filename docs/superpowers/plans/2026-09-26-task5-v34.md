# Task-5 v3.4 Shared Production-Overhead Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure and, only if qualified, remove one shared production overhead while preserving the complete Task-5 numerical contract.

**Architecture:** A measurement-only harness first attributes a single target across all three frozen slots. One private solver change follows only when its Amdahl bound qualifies; exhaustive correctness and two pre-registered performance stages gate review, merge, and canonical execution.

**Tech Stack:** C11, LAPACK/OpenBLAS, CMake/CTest, Python 3.13, NumPy/SciPy, pytest, ctypes, LD_PRELOAD/linker wrapping.

**Spec:** `docs/superpowers/specs/2026-09-26-task5-v34-design.md`

## Global Constraints

- Exactly four PDCA cycles and at most one production optimization.
- Preserve public API/ABI, numerical and certificate semantics, independent verification, one-router execution, frozen inputs, controls, and thread count.
- No harness-only optimization may support a solver-performance claim.
- No selective performance reruns.
- Historical campaigns, V3 workspace, stash state, and main history remain untouched.

## Review Focus

- Directed rounding must already be established for every product after any inner mode-set removal.
- Every early verifier return must restore the caller's rounding mode exactly as before.
- Nested or concurrent verifier calls must have no shared mutable state.
- Extreme/subnormal certificate cases must retain strict interval containment.
- A review correction touching timed code invalidates qualification timing and requires one complete replacement set.
