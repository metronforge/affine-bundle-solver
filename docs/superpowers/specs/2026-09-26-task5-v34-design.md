# Task-5 v3.4 Shared Production-Overhead Design

## Objective

Identify one production-side overhead shared by at least two bounded-large slots, prove that its removable fraction can plausibly lift the frozen v3.3 geometric-mean speedup from 1.4526577258x to 1.5x, implement only that optimization if qualified, and preserve every public, numerical, certificate, router, verification, and benchmark contract.

- Official thread variables: all supported BLAS/OpenMP variables equal 4

## Architecture

Cycle 1 adds measurement-only harness instrumentation that separates the supported API from caller preparation, validation, and harness overhead. It counts and attributes shared operations and independently estimates their removable cost. Only a target inside the supported API or unavoidable documented preparation may qualify.

If qualified, Cycle 2 changes one private implementation detail in the solver. Public standalone verifiers remain independent and complete; no global cache, public API, ABI, tolerance, rounding convention, or result field changes. Cycle 3 performs complete correctness/safety qualification and one pre-registered 11-trial branch comparison. Cycle 4 integrates only a qualifying exact head, then runs one independent post-merge 11-trial comparison and conditionally authorizes the canonical campaign.

## Candidate decision rule

A target qualifies only if measurements—not source inspection—show material time in at least two slots and its removable fractions give an Amdahl projection of at least 1.5x against the frozen legacy-equivalent controls. The leading candidate is redundant same-mode `fesetround` inside exponent-framed inconsistent-verifier product loops; callers already establish the required directed mode. This candidate is rejected if call counts, measured same-mode cost, or direct verifier timings do not provide sufficient leverage.

## Numerical invariant if the leading candidate qualifies

Each exponent-framed dot-product pass sets `FE_DOWNWARD` or `FE_UPWARD` before entering its loop. Every product in that pass requires the same mode. Removing a repeated inner `fesetround(mode)` changes neither the active mode nor the sequence of floating-point operations. The single-product lower-bound helper keeps its own explicit downward-mode establishment. Every verifier remains independently executed with unchanged inputs, operations, tolerances, outputs, and final restoration of the caller's rounding mode.

## Measurement protocol

Qualification and post-merge trials each use one excluded warmup plus exactly 11 eligible process-isolated trials per path and slot. Order alternates deterministically by slot and trial. No unfavorable result is selectively rerun. Exclusion is permitted only for an exposed thermal-throttle signal or a recorded execution failure, and all excluded records are retained. Report API-only and frozen end-to-end wall time, CPU, RSS, temperatures, frequencies, median, MAD, CV, paired ratios, and deterministic-bootstrap 95% intervals.

The branch comparison uses baseline solver `1621d104` versus the candidate with NULL `xt` on both paths. The final hard-gate comparison preserves the historical legacy-equivalent `f66cd87` plus preliminary SciPy GELSD control versus the merged NULL-`xt` candidate.

## Safety and stopping

Exactly one production optimization is permitted. Any new unregistered correctness failure, ABI change, review blocker, or performance qualification failure ends the implementation path without a second optimization. The canonical 27-slot campaign runs only after the hard 1.5x post-merge gate.
