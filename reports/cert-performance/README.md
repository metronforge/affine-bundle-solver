**Ориентир 20% достигнут.** На трёх плотных высоких системах медианное время выдачи сертификатов уменьшилось на **28,8%**, на двух отложенных — на **32,6%**. На широком входе 128×768 из предыдущего обсуждения выигрыш составил **3,5%**. Все сравниваемые поля публичного результата совпали.

# Выдача сертификатов для заданного кандидата

Вызов `bs_certify_candidate(A,b,x,...)` строит и проверяет профили UNIQUE, INFINITE и INCONSISTENT для близких систем. В каждом блоке обе версии получили одни и те же сохранённые A,b,x. Решение исходной системы, подготовка аргументов, наблюдение за свидетелями и файловый ввод-вывод выполнялись за пределами измерения. BASE — опубликованная ветка оптимизации solve, commit `361f068d9fa10b603e99ca12ccce6afe35784d90`. Изменение проверяющего завершено в `392e47501e9cbb7607017eeeb4e9edd0ffb753fd`.

Рабочее семейство выбрано по первому профилю: на высоких системах повторные проверки свидетеля несовместности составляли значительную долю полного вызова. Условия и размеры опубликованы в истории ветки до первой правки проверяющего. На входах семейства минимизировали время при побитовом равенстве радиусов и полном совпадении кодов. ## Причина выигрыша

Строгий проверяющий INCONSISTENT формирует интервал для скалярного произведения yᵀb и верхнюю границу нормы Aᵀy. Произведения вычисляются в общей степенной шкале, чтобы данные у границ binary64 сохраняли проверяемость. Изменены два шага.

1. Для выбора показателя шкалы достаточно найти наибольший модуль элемента расширенной строки и один раз определить его двоичный показатель. Это даёт тот же максимум, что и перебор показателей всех её ненулевых элементов. Самостоятельно изменение A дало отношение 0,918.
2. После подтверждения знака yᵀb проверяющий проверяет диапазон операндов. В допустимом диапазоне он точно масштабирует веса y один раз, проходит по нескольким столбцам за раз и округляет вниз и вверх в отдельных проходах. Для каждого столбца слагаемые поступают в прежнем порядке. Вне диапазона и при расширенной промежуточной точности используется исходное вычисление. Изменение B отдельно дало 0,814; добавление B к A дало 0,707 относительно A. [A](data/a.json) · [B](data/b-only.json) · [A+B против A](data/add-b.json)

На 2048×32 обе сборки проверили 11 свидетелей INCONSISTENT, из них два приняты. В профиле суммарное время этого проверяющего сократилось **с 7,67 до 1,64 мс**. В том же публичном вызове число динамических обращений к `fesetround` уменьшилось с 344 333 до 82 065, к `frexp` — с 1 384 452 до 143 364. В дополнительном независимом опыте восстановление исходного кода вернуло двоичный хеш библиотеки BASE; OFF → FINAL составило 19,95 → 12,31 мс. Дополнительная память быстрого пути — до 64 doubles на стеке, рабочие буферы прежних размеров. Для плотного свидетеля порядок стоимости проходов остаётся O(mn). ## Воспроизведение

На Linux с GCC, NumPy и SciPy выполните из checkout опубликованной ветки

```sh
bash reports/cert-performance/reproduce.sh
```

Скрипт создаёт две чистые сборки штатным `./build.sh`, сверяет SHA-256 всех NPZ и сохраняет сырые времена вместе с результатами сертификатов. В этой серии использовались AMD EPYC 9V74, GCC 14.2.0, один поток OpenBLAS и OpenMP, CPU 1, восемь чередующихся блоков и монотонный таймер. Частоты и температура виртуального хоста не контролировались. Для другого разрешённого номера CPU задайте переменную `CPU`. Границы интервалов относятся к замерам на одном хосте. [BASE manifest](data/rebuilt-base-manifest.json) · [FINAL manifest](data/final-manifest.json)

Для диагностики из корня репозитория при собранных `/tmp/cert-base` и `/tmp/cert-final`:

```sh
d=reports/cert-performance
gcc -O2 -shared -fPIC "$d/count_calls.c" -ldl -Wl,--no-as-needed -lm -o /tmp/cert-counts.so
gcc -O2 -shared -fPIC -Iinclude "$d/capture_witness.c" -ldl -o /tmp/cert-capture.so
for build in /tmp/cert-base /tmp/cert-final; do
    LD_PRELOAD=/tmp/cert-counts.so python3 "$d/count_calls.py" "$build" t1 t2 t3 w2
    LD_PRELOAD=/tmp/cert-capture.so python3 "$d/public_oracle.py" "$build" t1 t2 t3 w2 conflict
done
```

Для профиля функций создайте отдельный временный worktree нужной ревизии. Запустите `python3 reports/cert-performance/profile_cert.py /path/to/worktree`, затем `taskset -c 1 python3 reports/cert-performance/experiment.py /path/to/worktree - - t2 --worker --trace`. Инструментатор изменяет только этот временный worktree.
