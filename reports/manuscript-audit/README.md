Точная теорема о трёх типах сертификатов выдержала проверку при условии внешних границ ошибок. Общая гарантия исполняемой версии опровергнута: на конечном скалярном входе проверяющий код принимает радиус ноль при точном расстоянии один.

## Рекомендации Виктору по редакции статьи

**Во введении показать, какой вывод читатель вправе сделать после каждого публичного вызова.** Сейчас три операции описаны в разделе *Public operations and evidence boundaries*. В конец введения стоит вынести компактную таблицу, а технические подробности оставить в этом разделе.

| Вызов | Что получает пользователь | Как читать результат |
|---|---|---|
| `bsolve` | Кандидат x, численный статус и интервал ранга | Статус и интервал зависят от политики и пути вычисления. Fast BERR относится к внутреннему якорю маршрутизатора. |
| `abs_check_candidate` | Проверку переданного x на исходных строках | При корректной внешней оценке и сохранении субнормальной арифметики вердикт WITHIN_QUALITY_BOUND подтверждает порог для переданного x. Вердикт NOT_ESTABLISHED означает, что заданную точность подтвердить не удалось. |
| `bs_certify_candidate` | По каждому из трёх типов — радиус принятого объекта или отметку о его недоступности | Теорема гарантирует существование системы указанного типа в пределах радиуса при корректных внешних оценках ошибок. Для исполняемой проверки бесконечности решений известен ложный нулевой радиус. |

1. **Перенести скалярный пример сразу за доказательство теоремы о сертификатах.** Сейчас он следует после обсуждения замыканий и профиля. Для уравнения 2x=0 единственная скалярная система с бесконечным числом решений — 0x=0, на относительном расстоянии 1. При x=0 свидетель z=1 даёт верный радиус 1. Свидетель z=DBL_MAX задаёт то же направление, но проверяющий код принимает радиус 0. Такое соседство показывает, зачем теореме нужна предпосылка о внешних оценках. [Вход и вывод проверяющей функции](evidence/cert-probe.txt)
2. **Назвать вклад статьи в первом абзаце введения.** Указать, что при H=I−P, H₁=I и нулевом начальном приближении независимая вставка в точной арифметике совпадает с шагом Хуанга. Затем сформулировать результат статьи: для трёх типов точного статуса даны проверяемые конструкции в одной мере построчного возмущения. Формулы и первичную ссылку сохранить у теоремы о вставке. [Карта утверждений](claims.md)
3. **Оформить 155 диагностик как эксперимент с тремя исходами.** В разделе результатов числа уже приведены в абзаце. Таблица с колонками «округлена ли правая часть», «сохранилась ли точная несовместность» и «число случаев» позволит прочитать их без догадок: 80 точных переносов, 48 округлённых с сохранением несовместности и 27 округлённых с переходом к точной совместности. Рядом оставить отдельный опыт 3×2, где порог предсказал наблюдаемую смену статуса между e=30 и e=31. [Разбор по случаям](empirical.md)

Если центральный тезис статьи — математическая гарантия, в аннотации стоит назвать её арифметическую предпосылку и сразу указать границу реализации. Если автор заявляет надёжную выдачу сертификатов опубликованным ПО, для такого тезиса нужны исправление проверяющего кода и независимый повтор на тех же свидетелях, включая оба масштаба скалярного примера. ## Воспроизведение

В полном Linux-клоне с зависимостями проекта, компилятором, BLAS/LAPACK, Python и TeX, из корня репозитория:

```bash
git fetch origin
git switch ralph/manuscript-audit
bash reports/manuscript-audit/replay.sh
```

Скрипт собирает BASE и текущий HEAD в отдельных временных клонах, выполняет публичные контрпримеры, точные оракулы, штатные проверки и пересчёт исторических измерений. Для остальных хостов ожидаются качественные контрпримеры при тех же арифметических предпосылках; младшие биты результатов могут зависеть от компилятора и BLAS. Отдельные команды приведены в каждом разборе. PDF текущей версии собирается командой `bash build_paper.sh`.
