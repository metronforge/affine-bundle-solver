# Nearby-status certificates

**Decision. Keep the exact-real soundness theorem with its outward-arithmetic assumption. Withdraw the unconditional statement that each finite output of the current public API certifies a nearby system.** On clean main `1df77461faf407320dab200d025fa846b2151502`, the infinite verifier accepts a scalar problem at radius zero when its exact distance is one. Both the standalone candidate API and the ordinary combined solver also produce false zero radii. All three failures use finite binary64 inputs in the default gradual-underflow environment. [Public C probe](evidence/cert-probe.c) · [Recorded output](evidence/cert-probe.txt)

The lower bound in the middle row follows from $\Vert \Delta[A\ b]\Vert _F\le d_{\rm row}\Vert [A\ b]\Vert _F$ and the smallest source singular value as a lower bound for any rank-losing spectral norm perturbation. The last minor remains nonzero over the reals even though its numerical evaluation could underflow.

In the scalar case, the upper endpoint of $2z$ overflows. The row error bound becomes infinity, multiplication by $\Vert x\Vert =0$ produces NaN, and a NaN row quotient fails the comparison `q > best`. In the candidate case, the exact right null direction makes the coefficient correction zero, the upper norm of the large candidate overflows, and `0 * INFINITY` contaminates the RHS bound. The norm helper ignores NaN when searching for a largest exponent and can return zero for `(0,NaN)`. The final finite-maximum check therefore accepts. The ordinary combined API reaches the same branch with an internally generated large least-squares vector. The acceptable response for an unrepresentable bound is an unavailable coordinate with a rejecting verifier code. `src/status_certificate.c:53–77,351–376`, `src/certified_api.c:690–735,800–809,977–1009`.

## Support, signed underflow and the caller environment

Write $s$ for the number of nonzero augmented rows in a compatible system. Finite perturbations freeze the remaining rows. If $s<n$, no finite correction can make the coefficients injective. For instance the all-zero $2\times1$ source with zero RHS is infinitely solvable, with $d_{\rm inf}=0$ and $d_{\rm uniq}=d_{\rm inc}=+\infty$. If the $s$ active rows are independent, they admit a right inverse, and sufficiently small active-row perturbations remain compatible for every RHS. Thus the unqualified closure sentence after the proposition should explicitly retain its hypotheses. The C probe distinguishes a zero pivot row needing a nonzero correction, which is rejected, from an unchanged zero pivot in an already inconsistent system, which is accepted. Exact $y^Tb=0$ is rejected and products of signed factors with exponents differing by 1800 produce the correct enclosing sign in the test control.

In the shared norm helper, `scalbn(a[i],-e)` scales a signed value before squaring. Let $u=2^{-1074}$. Under upward rounding with $x=(2,-u)$, scaling the second component by $1/2$ gives negative zero. The helper returns exactly 2, below $\sqrt{4+u^2}$. With $x=(2,+u)$ it returns the next double above 2. This directly disproves a local outward-norm assumption. It does not by itself prove an extra false final certificate because subsequent inequalities can have slack. Scaling magnitudes and explicitly checking finite intermediates are separate requirements. For the downward norm of a finite vector, rounding a negative term away from zero on an inexact power-of-two downscale occurs only in the subnormal range, where the scaled square rounds down to zero. That specific example does not disprove the lower bound. [Same-source helper probe](evidence/cert-norm.c) · [Output](evidence/cert-norm.txt)

With caller-set x86 MXCSR FTZ/DAZ, both the unique and inconsistent public checks also accept false zero radii. In the unique control, two identical coefficient rows have right sides 0 and $u$. Zero radius leaves incompatible data. In the inconsistent control, the scalar source $ux=1$ is solvable, and the proposed correction changes its nonzero coefficient. Both calls give positive bounds under gradual underflow. These are separate from the default-environment infinite failures. The build's load-time MXCSR check cannot establish subnormal behavior for every calling thread at verification time. Either enforce the runtime assumptions per verification or state gradual underflow and supported rounding semantics as caller preconditions. [Public C output](evidence/cert-probe.txt)

## What the semantic fixture establishes

The test creates $b_0$ by rounding a floating matrix-vector product. Exact elimination modulo the odd prime $1{,}000{,}000{,}007$, mapping every stored binary64 numerator and power-of-two denominator into the field, gives first square coefficient and augmented minor residues 251354826 and 140960073. The exact real ranks on this run are therefore 8 and 9. The base source is already inconsistent. Perturbing only the last RHS cannot alter either of these leading minor witnesses. The 40-by-6 integer control has a four-column minor with residue 1800, two exact column relations and $b=A x$ over the integers. Its exact status is infinite. The local semantic regression passed both sections. Its passing tolerance checks and its incorrect compatibility description coexist. ## Minimal manuscript changes

1. In the abstract, public API description, profile paragraph and conclusion, use “Under valid outward bounds, each accepted object constructs a real system of the stated type within the reported radius. The current binary64 infinite verifier can accept a zero radius after overflow, including through the combined API.” Restore a stronger implementation claim only after repair and independent verification of the arithmetic.
2. Use “source-relative rowwise perturbation measure” and repeat “for compatible $m\ge n$ systems with nonzero augmented rows” when giving the simultaneous zero-distance corollary.
3. In the stress-test discussion, use “The Gaussian right-hand side was formed by a floating matrix-vector product. On the audited build, the stored augmented matrix has rank 9 and the coefficient matrix has rank 8. The unperturbed source is nearly compatible.” Reserve exact compatibility for the integer control or an independently verified exact fixture.
4. Describe the certificate battery as sampled checks with its fixtures, scaling axes and arithmetic precision. Specify that the build verifies its own loading behavior. Drop the universal signed-FMA-site claim. A production trust claim needs per-lane finite guards, correctly directed signed scaling and a defined floating-point environment.

## Replay

The first command group uses the already built, clean pinned tree at `/tmp/manuscript-main`. To use a different clean checkout of the same commit, run `bash build.sh` there and set `cert_build` to its absolute path. Run the commands below from the repository containing this review.

```sh
cert_build=/tmp/manuscript-main
cert_evidence=reports/manuscript-audit/evidence
cc -std=c11 -Iinclude "$cert_evidence/cert-probe.c" -L"$cert_build" \
   -Wl,-rpath,"$cert_build" -lcertified_solver -lstatus_verifier -o /tmp/cert-audit
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 ABS_CERT_UNIQUE_THREADS=1 /tmp/cert-audit
cc -std=gnu11 -O2 -fopenmp -frounding-math -fno-fast-math -ffp-contract=off \
   -Iinclude -Isrc "$cert_evidence/cert-norm.c" -lm -o /tmp/cert-norm
/tmp/cert-norm

   python tests/test_status_profile_semantics.py
```

The audit used GCC 14.2.0 and NumPy 2.3.5. The default-environment counterexamples require no modified library or exceptional caller mode. The optional MXCSR section in the C program is enabled on SSE2 builds and restores the caller's original register.
