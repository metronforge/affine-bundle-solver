# Страницы 1–9 и 21–29. Проверка для Виктора

**Две формулировки о качестве решения требуют правки до публикации.** На точно совместной системе 2×2 публичный `bsolve` выдал `UNIQUE` и fast BERR=0, а точная обратная ошибка возвращённого вектора равна ½. В другом опыте публичный `abs_check_candidate` принял ошибку 1 за ноль при включённом вызывающим потоком сбросе субнормальных результатов. Кроме того, все 12 заново сгенерированных систем из двух приложений на стр. 27 оказались точно несовместными. Маршрутизатор воспроизвёл все 12 опубликованных численных статусов и рангов. Эти три результата задают разные пределы применимости статьи.

Проверена редакция `107b5c1c0bae56b16645fa164b73b48f69722aad`. Штатная сборка дала 29 страниц. Идентификатор файла `paper.tex` — `2a72250e5350f5016ee5b6ad5e576192ec57b430`, тот же, что в [разборе стр. 10–20](middle-third.md). Нумерация включает титульную страницу. ## Два публичных контрпримера о качестве

**Реконструкция решения, стр. 5–6 и 21.** Пусть A=diag(1,t), b=(1,t). При t=1 и t=2⁻⁴² исходные системы точно совместны с единственным решением (1,1). У второй строки меняются единицы измерения, её решение сохраняется.

| t | Статус и интервал | Fast BERR | Выданный x | Точная η(x) | Ответ проверки x |
|---|---|---:|---|---:|---|
| 1 | UNIQUE [2,2] | 0 | (1,1) | 0 | WITHIN_QUALITY_BOUND, верхняя граница 0 |
| 2⁻⁴² | UNIQUE [2,2] | 0 | (1,0) | ½ | NOT_ESTABLISHED, верхняя граница ½ |

Для x=(1,0) вторая строка даёт невязку t и знаменатель t+t‖x‖=2t. В `solve_with_controls` первым вызывается роутер, затем `reconstruct_candidate_x`. Второй путь передаёт исходную матрицу в DGELSY с фиксированным `rcond=1e-12`; его рабочий ранг не переносится в интервал роутера. Здесь t ниже этого порога. Точная классификация UNIQUE верна в обоих случаях. Для решения, выданного клиенту, пример показывает потерю целой координаты в обычном диапазоне binary64. Альтернативный пример из §3.4 статьи затрагивал другую причину — добавку к знаменателю fast BERR. [Исходник вызова](../../src/certified_api.c) · [Данные](evidence/outer-checks.txt)

**Арифметическая среда, стр. 5, 23 и 26.** Для одной строки взять a=x=2⁻⁵³⁰, b=0. Произведение равно представимому числу 2⁻¹⁰⁶⁰, точная η=1. При постепенном андерфлоу проверка дала остаток 2⁻¹⁰⁶⁰, η_up=1 и NOT_ESTABLISHED. На той же сборке x86 с включёнными вызывающим потоком FTZ и DAZ она дала остаток 0, η_up=0 и WITHIN_QUALITY_BOUND. После опыта восстановлен прежний MXCSR. Этот контрпример касается фиксированного x и согласуется с ранее обнаруженными ограничениями других строгих операций. [Программа](evidence/outer-api.c) · [Данные](evidence/outer-checks.txt)

## Что именно классифицируют прикладные примеры

Выполнен генератор из приложения с опубликованными размерами, seed и четырьмя потоками OpenMP для роутера. BLAS использовал один поток. Для каждой строки ниже оракул и C-функция получили одни и те же массивы. Численные ответы сверены с `results/applications_final.json`. Хеши относятся к заново сгенерированным массивам на данном хосте; исторический JSON содержит результаты и не устанавливает побайтового тождества с массивами первоначального запуска.

| L | Область | Численный статус / ранг | Точный ранг A | Точный ранг [A,b] |
|---:|---|---|---:|---:|
| 7 | вся сфера | UNIQUE / 64 | 64 | 65 |
| 7 | экватор | INFINITE / 15 | 57 | 58 |
| 11 | вся сфера | UNIQUE / 144 | 144 | 145 |
| 11 | экватор | INFINITE / 23 | 133 | 134 |
| 15 | вся сфера | UNIQUE / 256 | 256 | 257 |
| 15 | экватор | INFINITE / 31 | 241 | 242 |

Каждое сохранённое число binary64 есть точная двоичная дробь. Оракул отображает её в поле по модулю 1 000 000 007, где знаменатель обратим. Ненулевой определитель в этом поле доказывает ненулевой рациональный минор. На всей сфере берутся k=n столбцов. На экваторе все L+1 зональных столбцов с индексами ℓ² постоянны по всем строкам, что проверено непосредственно. Нулевой по индексу столбец отличен от нуля, поэтому остальные L зональных столбцов можно удалить без изменения ранга. Остаются k=n−L столбцов. В каждом случае ненулевы ведущий минор порядка k выбранных столбцов и минор порядка k+1 после добавления b. Число столбцов даёт соответствующие верхние границы. Поэтому точный ранг расширенной матрицы **строго выше** во всех шести случаях. Это доказательство для конкретных данных, включая округлённое `b=A@x`. Аналитический функциональный ранг экватора 1+2L сохраняет свой обычный смысл. [Код оракула](evidence/outer-applications.py) · [Миноры и SHA-256](evidence/outer-checks.txt)

Для радиосетей достаточно исходных трёх строк. Для рёбер 0→1, 1→j, 0→j сумма первых двух коэффициентных строк точно равна третьей. Совместность требует такой же связи между тремя правыми частями. Оракул нашёл ненулевой дефект во всех шести наборах. Например, для N64 с опорной фазой это −3/2⁵⁶, хотя роутер сообщает UNIQUE/64. В намеренно возмущённом N256 роутер сообщает INCONSISTENT/255; найденный треугольник доказывает противоречие даже без добавленной строки. Таким образом, **11 из 12** численных статусов двух приложений расходятся с точным классом восстановленных входов. Это совместимо с контрактом численной политики. В приложении стоит показать отдельно класс идеальной конструкции, выход роутера и точный класс хранимых данных. [Все двенадцать результатов](evidence/outer-checks.txt)

## Насколько узок интервал переноса на стр. 7

В точной одномерной модели взять P=1, x=0, â=c₀=1 и t_c=½. При β=1+2⁻ᵏ, k≥1, имеем ρ=β, K=2 и B₀=1+β. Из формул предложения 3.1 следуют S_keep=(β−1)/2 и S_drop=(3β−1)/2. Ширина в показателях равна log₂(S_drop/S_keep)=log₂(2ᵏ⁺¹+3). Уже k=30 даёт более 31 порядка. Сам параметр β при k=30 точно представим в binary64. Это граница достаточных оценок; фактический переход для опубликованного опыта 3×2 по-прежнему воспроизводится между e=30 и 31.

## Воспроизведение

Из корня ветки на Linux с зависимостями проекта:

```bash
bash build.sh
bash build_paper.sh
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
audit=reports/manuscript-audit/evidence
scratch=$(mktemp -d)
cc -O2 -Iinclude "$audit/outer-api.c" -L. -Wl,-rpath,"$PWD" \
  -lcertified_solver -laffine_bundle_solver -o "$scratch/api"
"$scratch/api"
python "$audit/outer-applications.py"
bash "$audit/rank-replay.sh"
python "$audit/empirical-rerun.py" "$PWD"
python "$audit/empirical-exact.py" "$PWD"
python "$audit/empirical-records.py"
```

Для последней команды нужны объекты двух исследовательских веток, перечисленные в [реестре версий](README.md). Пересчёт времени таблиц выполнен по неизменяемым данным исходного ноутбука. В этом постраничном аудите новые измерения скорости не проводились.
