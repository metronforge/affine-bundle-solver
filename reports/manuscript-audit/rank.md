# Rank evidence, arithmetic bounds, and translation policy

This review cites the submitted text and source at `1df77461faf407320dab200d025fa846b2151502`. Two mathematical results survive the audit. The two-pass residual identity holds in exact arithmetic for the stored basis. The provenance inequality proves an exact rank lower bound whenever its input envelopes hold. The published fast-router quality guarantee has a counterexample, and two numerical bounds used to connect the implementation to the provenance theorem fail on reproduced inputs. These findings concern the operational router and its formation guard. The separate verifier of nearby statuses has a different arithmetic contract.

## Public results that change under exact row scaling

**R1. The fast UNIQUE quality gate can accept a system for which every possible solution candidate exceeds the stated tolerance.** The fixed-candidate expression at `paper.tex:243–253` is mathematically correct, with zero error for a zero residual and zero denominator. For a nonzero residual the admissible perturbations can supply exactly the sum of the two allowances, including the cases of a zero coefficient or a zero right-hand side. The implemented quantity differs. Both branches of `compat_scan_fused` add `1e-300` to the denominator, and the small-width branch may report a ratio using the infinity norm of the coefficient row. Both branches evaluate the residual in fast binary64 arithmetic. The custom-quality branch also includes the additive floor. See `src/bsolver.c:256–266,513–529,947–989,1026–1043`.

Let the two scalar equations have coefficients \(s,s\) and right-hand sides \(s,s(1+2^{-32})\). With \(s=1\), the default public router returns UNDECIDABLE, rank interval \([1,1]\). With \(s=2^{-1015}\), it returns deterministic UNIQUE, interval \([1,1]\), reference error zero for \(x=1\), and BERR \(6.6311990742\times10^{-16}\). All nonzero inputs are normal binary64. For that \(x\), the exact mixed backward error is \(1/(2^{33}+1)=1.1641532181\times10^{-10}\). The best achievable value over all real \(x\) occurs at \(\sqrt{1+2^{-32}}\), where the two row errors agree. It is \(2^{-32}/(1+\sqrt{1+2^{-32}})^2\), about \(5.82\times10^{-11}\). The additive floor changes the verdict. With the same input `bsolve` returns an explicit candidate \(1.0000000001164149\) and the same router BERR. The strict `abs_check_candidate` applied to that returned candidate gives NOT_ESTABLISHED with mixed upper bound \(5.8207882948\times10^{-11}\). The analytic lower bound establishes that the requested \(10^{-14}\) tolerance fails independently of that upper bound.

**Correction.** Describe the displayed formula as the mathematical target. Identify BERR as the fast router's diagnostic for its internal anchor. State that `abs_check_candidate` supplies a separate outward upper bound for a supplied candidate when available. A universal guarantee for a returned solution would require a successful strict check on that particular vector prior to returning guaranteed status. An unresolved quality decision can have a point rank interval, as the unscaled control illustrates.

**R2. An exactly dyadic row rescaling moves a default grey direction to resolved growth.** Take rows \((1,0)\), \(f(1,2^{-30})\) and a zero right-hand side. Scale the second row from \(f=9/8\) to \((9/8)2^{-537}\). Every nonzero input is normal. In both systems the exact normalized distance of the second direction from the first is \(2^{-30}/\sqrt{1+2^{-60}}<10^{-9}\). The first call returns UNDECIDABLE \([1,2]\). The scaled call returns deterministic UNIQUE \([2,2]\), with zero formation-guard checks. On this build the rounded sum of the second row's squares is \(2^{-1074}\). The fast norm accepts this positive finite sum and returns \(2^{-537}\). The resulting normalized transverse component is \((9/8)2^{-30}>10^{-9}\). See `src/bsolver_core.c:55–57`, `src/bsolver.c:188–205,573–582`, `include/affine_bundle/router.h:101–125`, and `paper.tex:230–237`.

**Correction.** Specify the default thresholds as comparisons on *computed* normalized data. Proving a scale-independent numerical interpretation would require scaled norm and normalization arithmetic which controls relative accuracy even when a positive sum of squares is subnormal. A guard which switches only on zero or overflow misses this case.

## Exact provenance inequality and executable bounds

**R3. Mathematical theorem retained.** Write \(K^{\star T}R^{-1}=Q+(F+(K^\star-\widehat K)^T)R^{-1}\) on the selected rows. Its smallest singular value is at least \(\sqrt{1-\eta}-\chi(\phi+\varepsilon_J)\). Strict positivity gives rank \(r\), all source traces lie in the source row space, and \(R\) is invertible. Equality provides no positive margin. For example \(r=n=1\), \(Q=R=\widehat K=1\), \(F=0\), \(K^\star=A=0\), \(\epsilon=1\) attains equality at source rank zero. The inverse estimate follows from \(R^{-1}=X(RX)^{-1}\) when \(\|I-RX\|<1\). This proves exact rank *at least* \(r\) under the hypotheses. A numerical-rank threshold, exact rank upper bound and entire exact status require other evidence. See `paper.tex:375–423`.

**R4. The normalization budget can underestimate the distance to the specified source trace.** The paper takes \(k^\star=c^\star/\nu\). The strict bound charges for one correctly rounded division per coordinate, while the normalization loop runs under `-ffast-math`. In a compiled call to the production helper `proof_rows_add_normalized`, give all nine raw coordinates the same binary64 value `0x1.f4c4962e56146p+0`, with zero raw error. The intercepted common divisor is `0x1.779370a2c08f5p+2`. Every stored coordinate is `0x1.5555555555554p-2`, equal to the rounded product with the rounded reciprocal. Direct correctly rounded division gives `0x1.5555555555555p-2`. Exact rational evaluation gives \(\|\widehat k-c^\star/\nu\|_2=1.4636960395\times10^{-16}\), **1.31838 times** the claimed budget. The vector in this example remains in the exact one-dimensional source span. It falsifies the prescribed trace bound without establishing a false rank decision. See `paper.tex:360–371`, `src/bsolver.c:380–386`, `src/formation_guard.c:85–103`, and `build.sh`'s separate router and guard flags.

**Correction.** Perform trusted normalization using the strict operations the budget covers, or specify the actual common multiplier as the trace scalar and bound the error of each multiplication, including scaling of earlier formation error. Mixed scalar/vector code also needs one common trace definition. The stored proof rows and scalar budgets describe a conceptual exact trace. The implementation does not store an exact-real vector for each row.

**R5. The Frobenius upper-bound helper sometimes rounds below the exact norm.** On Linux x86-64 with a 64-bit long-double significand, use entries \(1\) followed by 20,000,000 copies of \(2^{-32}\). The exact squared norm is \(1+20{,}000{,}000\,2^{-64}\). Each small square is exactly halfway between adjacent long-double values when added to one, so nearest-even summation repeatedly returns one. The strict production helper returns `0x1.00000000007a2p+0`. Its square is below the exact squared norm by \(2.1645\times10^{-13}\). The loop covers the whole vector, but the widening uses an operation count capped at one million entries. These norms feed \(\|R\|_F,\|X\|_F,\|Q\|_F\). This demonstrates an unsound intermediate upper bound. Other terms can add slack, and this test does not establish a false final compressed-rank acceptance. See `src/formation_guard.c:74–82,200–236`.

Also, expressions such as `2*r*r+32` and `2*r*n+32` are evaluated in signed `int`. At \(r=n=32768\) the former exceeds INT_MAX on the audited ABI. The public policy dimension guards permit dimensions for which those products exceed INT_MAX. The tested norm accumulation benefits from an extended exponent range on this platform. On platforms where long double equals double, intermediate squares may underflow or overflow earlier. External DGEMM operations require a suitable dot-product error model independently of the C compilation flags. These are additional arithmetic hypotheses, not reproduced false final decisions.

**Correction.** Use an outward, scaled norm for the actual entry count and checked wide arithmetic for all dimensions and operation counts. Fail closed if the arithmetic model or count cannot justify a bound. In the manuscript retain the theorem and describe the current executable check as an attempted sufficient test whose universal arithmetic hypotheses remain open. The two specific counterexamples make an unconditional claim of verified executable inputs untenable even on the tested compiler.

## Which routes and intervals receive which evidence

The auto/global compressed paths form signed source combinations, track their accumulated scale and term counts, normalize the selected core rows, and call the dedicated QR residual, inverse and Gram test on candidate growth. The block-prefix path also collects validator and correction rows that may propose growth. Validators used only to screen a candidate can be generated without a stored formation budget, including the automatic/global validators and secant-tail validators. Local source insertions and the guarded LU lane use different numerical checks. An unambiguous source QRCP proposal can reach the formation test and, after a failed test, a slower prefix check. A grey source-QRCP decision returns earlier. See `src/bsolver.c:391–398,451–462,504–509,581–604,617–636,698–711,728–751,755–798,861–888,929–970`.

**R6. A public lower endpoint can exceed the exact source rank.** For \(A=(3,7,11)^T(1,2,3)\) and \(b=0\) the exact rank is one. With the accepted custom thresholds \(\tau_d=10^{-34},\ \tau_g=2^{-60}\), the public policy API returns UNDECIDABLE \([2,3]\), zero formation checks and exact status UNKNOWN. It counts the rounded normalized source-QRCP pivots before the grey return. The default-policy control on this build returns randomized INFINITE \([1,3]\). The API explicitly defines operational status, so the example establishes a scope distinction. It does not refute the exact provenance theorem.

**Correction.** Describe public rank endpoints as route- and policy-dependent numerical diagnostics. Reserve “certified source-rank lower bound” for a successful proof with justified inputs. Avoid claiming that all deterministic rank growth passes this theorem, particularly in the abstract and router summary at `paper.tex:59,778`. The lower endpoint for the custom-policy grey case does not receive such a proof. The upper endpoint of a randomized closure is the dimensional limit \(\min(m,n)\), directly enforced at `src/bsolver.c:1028–1033`.

| Decision | Implementation and endpoint semantics |
|---|---|
| Guarded source row | Growth if computed lower distance is strictly above \(10^{-9}\). Dependence if upper is strictly below \(10^{-13}\). A candidate contradiction below full rank also requires local augmented singular-value ratio strictly below \(10^{-14}\). Equality stays grey. |
| Source QRCP | Lower endpoint counts \(d_i>\tau_g\), upper counts \(d_i\ge\tau_d\), and equality at either threshold records a grey row. With custom \(\tau_g=1,\tau_d=1/2\), identity gives \([0,2]\). The meta API usually prefers this interval on an unresolved result. |
| Core SVD diagnostic | Lower and upper counts use strictly greater than \(10^{-9}\) and \(10^{-12}\); ambiguity uses the closed interval. For an exactly represented input diagonal \((1,\mathrm{binary64}(10^{-12}))\), the direct core helper returned ambiguous with diagnostic \([1,1]\). At the stored upper threshold it returned ambiguous \([1,2]\). Preserve this distinction from the public source-QRCP interval. |
| Unresolved due solely to quality | The rank can already be resolved, as R1's \([1,1]\) shows. FAIL carries no rank evidence. |

## Projection, translation and router descriptions

**R7. Exact two-pass projection identity retained.** With \(Q=U\Sigma V^T\), the difference between \((I-QQ^T)^2\) and \(I-P\) is \(U(I-\Sigma^2)^2U^T\). Its spectral norm is exactly \(\|Q^TQ-I\|_2^2\). This bounds the exact residual-norm discrepancy for unit input. For a general input multiply by \(\|a\|_2\). The computed dot products and norm evaluations need additional error bounds. The incremental Gram calculation on stored \(q=(1,2^{-27})\) returns zero defect although its true defect is \(2^{-54}\). For inserted rank at least 96 the code uses a propagated estimate; backend bases start with a dimension-scaled allowance. The fixed evaluation cushion \(64\epsilon_{\rm mach}(1+\eta)\) has no stated proof for the entire supported dimension range. This example alone does not show the padded interval fails. R2 independently shows inaccurate source normalization can change the public decision. See `paper.tex:305–358,425,762–767`, `src/bsolver_core.c:55–71`, and `src/bsolver.c:85–111,138–145`.

**Correction.** Use “exact-arithmetic envelope; implementation uses a padded estimate” for the local distance. Both rank regimes implement matrix-form CGS2. The small-rank loop computes every coefficient before updating the vector and is classical Gram–Schmidt. The threshold at 96 switches to BLAS. The earlier “modified Gram–Schmidt” description conflicts with the appendix and the code.

**R8. The translation bracket assumes the chosen anchor actually translates by the full shift.** For a prescribed pair \(x,y=x-c\), \(\rho' = \rho\) exactly. Forward and reverse triangle inequalities give the stated sufficient thresholds when \(K>0\) and the logarithms have positive arguments. Equality is excluded on the preservation side and included on the guaranteed-drop side. The zero ray has no transition. For a *recomputed canonical* prefix anchor the affine model's minimum-norm representative translates as \(y=x-Pc\), where \(P\) projects onto the prefix row space. For a dependent row the residual remains invariant because \(a^T Pc=a^Tc\). The anchor term changes the slope to \(K_P=|\hat a^Tc_0|+\|Pc_0\|\). If \(K_P=0\) the gate is unchanged.

For example, \(A=((1,0),(1,0))\), \(b=(0,1)\), \(c_0=(0,1)\) produce exactly the same input for every dyadic shift. With the first equation as the prefix the canonical anchor is zero, and the second equation stays contradictory. The original formula applied as a router prediction would have \(K=1, S_{\rm drop}=5\times10^9\). The compiled router remains INCONSISTENT at \(2^{40}\). In the controlled \(3\times2\) experiment the first two equations span the whole space, so \(P=I\) and the prescribed-anchor formula applies. The property battery draws a fresh shift direction at each exponent, and it does not record a row's tested anchor or bracket. The exact augmented ranks and rounding effects for those diagnostics are reviewed in the empirical evidence. See `paper.tex:257–302,932–941,982,991`, `experiments/affine_translation_policy_gate.py`, and `tests/pbt_equivalence_orbits.py:127–129,190–194,259–264`.

**Correction.** State the bracket for a fixed pair of translated anchors or replace the slope with \(K_P\) for a common canonical prefix and dependent row. Separate the controlled example from case-by-case attribution in the property battery. The inequalities describe a row gate under these hypotheses. Final class also depends on the rank route and quality gate.

**R9. Sketch dimension.** On the auto and block-prefix routes the code sets \(d_h=n+1-r\), then \(k=\max(1,\min(m-p,d_h+\lfloor d_h/8\rfloor+4))\). The correction round also caps by the previous \(k\). If “remaining rank defect” means \(n-r\), the formula at `paper.tex:753–760,1030` is off by one in its input. The global route instead uses \(\min(m,\alpha(n+1))\) with a lower cap of one. State that one sparse contribution and two validators are the reported default configuration. The public controls allow other positive values. See `src/bsolver.c:583,618,755,771`.

## Reproduction

From the audited checkout on Linux, use the built public libraries and run `ABS_LIB_DIR=/path/to/build bash reports/manuscript-audit/evidence/rank-replay.sh`. The public harness links to the clean baseline libraries whose hashes appear in the transcript. The file-local projection, SVD and normalization probes compile the baseline router source with the production fast arithmetic flags. The normalization wrapper records the divisor at the boundary and forwards all arguments to the real strict function. Its trace inequality is compared using Python exact fractions. The file-local norm test compiles the actual guard with the strict flags and targets a 64-bit long-double significand. The file-local harnesses link system BLAS/LAPACK. Existing threshold, core-rank-boundary and block-prefix-guard tests pass against the clean baseline. Their samples do not exercise these counterexamples.
